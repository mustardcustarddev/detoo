# detoo documentation site

The documentation and blog published at
<https://mustardcustarddev.github.io/detoo/>, built with [Astro](https://astro.build/).

## Running it

You need Node.js 22.12 or later, and Go, since the command reference is
generated from the tools.

```bash
npm install
npm run dev                 # generate the command pages, and serve on localhost:4321/detoo/
npm run build               # generate the command pages, and build into dist/
npm run check-links         # after a build: fail on any internal link that leads nowhere
npm run check               # type-check
```

From the repository root, `make site` installs, builds and checks the links in
one step.

## Where the pages come from

| Pages | Source |
| --- | --- |
| Getting started, guides, agent skills | Markdown in `src/content/docs/` |
| One page per tool and per command | Generated into `src/content/reference/` by `tools/sitegen` |
| Blog posts | Markdown in `src/content/blog/` |

The command pages show exactly what each tool prints for `help`, such as
`adr help new`. They are generated by `go run ./tools/sitegen` before every
`dev` and `build`, and are not committed. To change one, change the tool's
help in `internal/*/help/`.

## For language models

Every docs page is also served as Markdown beside it, such as
`docs/adr/new.md` for `docs/adr/new/`, and the introduction as
`docs/index.md`. `llms-full.txt` holds every page in one file, in the order
of the contents, and `llms.txt` lists them, following
[llmstxt.org](https://llmstxt.org/). All three are generated from the same
sources as the pages, by `src/lib/markdown.ts`, with links made absolute so
that they still work once pasted elsewhere. The "Copy page" button on each
docs page copies its Markdown, or opens it as plain text.

## Adding a page

Add a Markdown file to `src/content/docs/`, with frontmatter:

```yaml
---
title: Custom templates
description: One line for search results, 160 characters at most.
section: guides # getting-started, guides or skills
order: 3 # its place in the section
---
```

The sidebar lists it under its section, in order. Its address is its path
under `src/content/docs/`, so `guides/templates.md` is `docs/guides/templates/`.

## Adding a post

Add a Markdown file to `src/content/blog/`. Its file name is its address.

```yaml
---
title: Plan for the incident before it happens
description: One line for search results and the feed, 160 characters at most.
pubDate: 2026-10-17
tags: [piosee, incidents]
tool: plm # optional: the tool the post ends by pointing to
draft: true # shown by `npm run dev`, left out of the built site
---
```

## Links

The site is served from `/detoo/`, not the root, so write every internal
link with `url()` from `src/lib/url.ts`, such as `url('docs/install/')`, and
never as `/docs/install/`. In Markdown, link relatively, such as
`../install/`. `npm run check-links` catches any link that misses.

`SITE_URL` and `BASE_PATH` override where the site is served from, for a
custom domain or a fork:

```bash
SITE_URL=https://docs.example.com BASE_PATH=/ npm run build
```

## Publishing

`.github/workflows/site.yml` builds the site on every pull request that
touches it, and builds and deploys it to GitHub Pages on every push to
`main`. Before the first deployment, set the repository's
**Settings › Pages › Source** to **GitHub Actions**.
